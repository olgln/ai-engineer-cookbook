# 13.1 · Резюме  (AIL-53)

> **Неделя 13** · Портфолио · ⏱ ~4–5 ч · Проект

## Зачем это AI-инженеру

Резюме — фильтр перед любым разговором: его читают ATS, рекрутер и нанимающий менеджер, каждый по-своему. На рынке AI Engineer резюме «знаю LangChain, OpenAI, Pinecone» — массовые, и проходят те, где видна позиция и результат: бэкенд с real-time и деньгами плюс LLM-проекты с измеренным качеством. Позиционирование важнее списка технологий.

## Теория

### Кто и как читает резюме

```
ATS (автомат)         Рекрутер (6–30 сек)          Нанимающий менеджер (1–3 мин)
 ─ парсит текст        ─ заголовок = вакансия?       ─ что строил, масштаб
 ─ ключевые слова      ─ годы/уровень, локация       ─ цифры и решения
 ─ отбрасывает         ─ ключевые слова глазами      ─ ссылки: GitHub, статья
   нечитаемое          ─ «внятно или каша»           ─ о чём спросить на интервью
```

Следствия:

- **ATS:** обычный текст в PDF, одна колонка, стандартные заголовки (Experience, Projects, Skills, Education). Таблицы, текст в картинках, иконки вместо слов и экзотические шрифты ломают парсинг. Ключевые слова из вакансии должны встречаться в тексте дословно («LLM», «RAG», «Python»).
- **Рекрутер:** первая треть страницы решает. Заголовок и summary должны совпадать с названием вакансии.
- **Менеджер:** ищет доказательства. Каждый пункт — что сделал, как, с каким результатом.

### Позиционирование

Твоя история: опытный TypeScript/Node-разработчик, который построил и эксплуатирует real-time торговую систему, а теперь делает LLM-продукты с измеримым качеством. Это не «джун в AI», а «бэкенд-инженер, который добавил LLM-стек». Такая позиция сильнее, потому что большая часть работы AI Engineer — это бэкенд: API, очереди, ретраи, стоимость, наблюдаемость, надёжность.

Заголовок: **Backend / AI Engineer**. Под каждую вакансию его можно сдвигать: «AI Engineer» для AI-продуктовых компаний, «Backend Engineer (LLM)» для бэкенд-вакансий с LLM-частью, «Backend Engineer, Fintech» для трейдинга.

Summary (2–3 строки, без прилагательных):

> Backend / AI Engineer. Built and run a real-time crypto arbitrage system in TypeScript/Node (8 exchanges, WebSocket market data, automated execution, Telegram ops). Build LLM applications with measured quality: RAG with hybrid search and reranking, tool-calling agents, MCP, evals.

### Формула пункта

Классическая формула (её часто приписывают рекрутингу Google): **«Достиг X, измеренного Y, сделав Z»**. В инженерной версии: глагол действия + что + как + результат с цифрой.

| Плохо | Хорошо |
|---|---|
| Работал с RAG | Built a RAG system over exchange API docs; hybrid BM25 + vector search and a reranker raised recall@5 from 0.62 to 0.87 on an 80-question eval set |
| Использовал Claude API | Built a Telegram bot answering questions over a read-only trading DB via tool calling; 92% correct tool calls on 50 test questions, ~$0.004 per answer |
| Отвечал за торговую систему | Designed a real-time arbitrage engine: WebSocket order books from 8 exchanges, simultaneous two-leg execution, naked-leg protection, SQLite with numbered migrations |

Цифры — плейсхолдеры: только реальные, из своих evals и логов. Каждую цифру ты должен уметь объяснить на собеседовании: как мерил, на чём, какой baseline.

Где брать цифры для торговой системы, не раскрывая денег: число бирж, число одновременных стримов, время реакции, число миграций схемы, покрытие тестами, uptime, число предотвращённых инцидентов. **Не указывай** PnL, объёмы, балансы — это лишнее и потенциально проблемно; инженерный масштаб убеждает лучше.

### Структура на одну страницу

```
Имя Фамилия — Backend / AI Engineer
Город / remote · email · Telegram · github.com/... · linkedin.com/in/... · статья

SUMMARY (2–3 строки)

EXPERIENCE
  Роль — Компания/проект, даты
   • 3–5 пунктов по формуле
  (торговая система: как independent project / self-employed, если не было работодателя)

PROJECTS (LLM)
  exchange-docs-rag — одна строка с цифрой + ссылка
  rag-evals-lab     — одна строка с цифрой
  trade-review-agent— одна строка с цифрой
  trading-assistant-bot        — одна строка с цифрой

SKILLS (сгруппированно)
  LLM: RAG, embeddings, tool calling, agents, MCP, evals, prompt caching
  Languages: TypeScript, Python
  Backend: Node.js, WebSocket/socket.io, SQLite, Docker, REST
  LLM APIs: DeepSeek, Ollama (local models), Anthropic/OpenAI (если вызывал)
  Tools: Pydantic, Langfuse/promptfoo, OpenAI-compatible SDK

EDUCATION / LANGUAGES (коротко; English: уровень)
```

Одна страница — жёсткое правило для твоего уровня опыта в AI. Если не влезает — режь старое и нерелевантное, а не уменьшай шрифт.

### Проекты: одна строка

Задача требует «каждый проект — одна строка с цифрой результата». Это дисциплинирует: если не можешь описать проект одной строкой с цифрой, его сложно будет продать и на собеседовании. Шаблон строки: `название — что делает (стек); главная цифра (baseline, n) — ссылка`.

### Русская и английская версии

Это не перевод, а адаптация:

| | RU (hh.ru, Хабр Карьера, Telegram-каналы) | EN (LinkedIn, международные компании) |
|---|---|---|
| Заголовок | «Backend / AI Engineer» — так же на английском, это нормально | Backend / AI Engineer |
| Фото | На hh.ru принято, но необязательно | Обычно без фото (в США и части Европы — нежелательно) |
| Формат | На hh.ru резюме заполняется в форме сайта + можно приложить PDF | PDF |
| Зарплата | Часто указывают ожидания | Обычно не в резюме |
| Стиль | Можно «Разработал…», «Сократил…» | Глаголы в прошедшем времени без «I»: Built, Designed, Reduced |

Термины (RAG, evals, tool calling) в русской версии оставляй английскими: так ищут и рекрутеры, и ATS.

### Чего не писать

- «Ответственный, коммуникабельный, стрессоустойчивый» — без информации.
- Шкалы навыков («Python ●●●●○») — непонятно, что значат, и ломают ATS.
- Курсы как опыт работы. Курсы — в Education одной строкой или никак; проекты — отдельно.
- «Expert in LLM» после трёх месяцев. Честное описание сделанного убеждает лучше.
- Причины ухода, семейное положение, полный адрес, дата рождения (в EN-версии).

### Ссылки

GitHub, LinkedIn, статья — кликабельные, с коротким видимым текстом (`github.com/<you>`). Проверь, что PDF сохраняет ссылки (при экспорте из некоторых редакторов они теряются). Имя файла: `Firstname_Lastname_AI_Engineer_EN.pdf` — рекрутер скачивает десятки `resume.pdf`.

### Инструмент

Подойдёт любой редактор, дающий чистый PDF с выделяемым текстом: Google Docs, Word, или Markdown/Typst/LaTeX, если тебе так удобнее и хочется держать резюме в git. Главная проверка — скопируй весь текст из PDF в обычный текстовый редактор: если порядок и слова сохранились, ATS тоже прочитает.

## DeepSeek и Ollama: как это сделать у нас

Две вещи: как написать провайдеров в резюме и на какой модели резюме проверять.

**Как писать.** ATS ищет дословно, а в большинстве вакансий AI Engineer стоят «OpenAI API» и «Anthropic/Claude» — проверь на своём словаре вакансий. Поэтому:

- в Skills — честный список: DeepSeek, Ollama, и Claude/OpenAI, только если ты их реально вызывал (в главе [12.1 · Профиль GitHub и LinkedIn](AIL-67.md) ты сделал хотя бы один сравнительный прогон — вот он и даёт право);
- мультипровайдерность — отдельный пункт-доказательство, а не оправдание: *«Built a provider-agnostic LLM layer (OpenAI-compatible API): DeepSeek for cloud runs, local models via Ollama for private data; compared providers on an 80-question eval set — <результат>»*;
- под вакансию, где важна приватность или self-hosted (финтех, банки), этот пункт поднимай выше: «real data never left the machine» — редкий и понятный аргумент.

| | Claude | OpenAI | DeepSeek | Ollama |
|---|---|---|---|---|
| Ключевое слово для ATS | Anthropic API, Claude | OpenAI API | DeepSeek | Ollama, local LLMs, self-hosted |
| Можно писать, если | вызывал хотя бы в сравнении | то же | основной облачный провайдер проектов | основной локальный провайдер |
| Чем подкрепить | строка в таблице сравнения | то же | стоимость на ответ, кэш | приватность, $0 за токены, железо |

**На чём проверять резюме.** В резюме твои личные данные: имя, email, телефон, Telegram, город. Это не торговые данные, но всё равно личное, а DeepSeek хранит данные в Китае (по своей политике конфиденциальности, проверено в ноябре 2026). Варианты: перед ревью через DeepSeek заменить контакты на заглушки (`<NAME>`, `<EMAIL>`), или гонять ревью через Ollama локально. Ревью «глазами рекрутера» хорошо даёт и сильная облачная модель — для сравнения прогони тот же промпт через Claude или OpenAI (тоже без контактов) и посмотри, совпадают ли замечания.

## Маршрут изучения

1. Открой https://www.techinterviewhandbook.org/resume/ → прочитай целиком (≈30 мин). Обрати внимание на формулу пунктов, требования ATS и список типовых ошибок; возьми их чек-лист.
2. Открой 5–10 вакансий AI Engineer / LLM Engineer, на которые реально будешь откликаться (LinkedIn Jobs, hh.ru, Хабр Карьера) (≈40 мин). Выпиши в `notes/resume.md` повторяющиеся ключевые слова и требования. Это твой словарь для резюме.
3. Перечитай `notes/portfolio.md` из главы [12.1 · Профиль GitHub и LinkedIn](AIL-67.md) и цифры из README ([глава 12.2 · README, схемы и демо для всех проектов](AIL-50.md)) (≈15 мин) — это материал для пунктов.
4. Найди в справке hh.ru раздел о составлении резюме (≈15 мин) — там описаны поля, по которым ищут работодатели; актуальные формулировки смотри на сайте.
5. В своём словаре вакансий (шаг 2) посчитай, сколько раз встречаются OpenAI, Anthropic/Claude, DeepSeek, Ollama / local LLM (≈5 мин). Это решает, какой провайдер ставить в Skills первым. Если хочешь свериться с текущими условиями DeepSeek — https://api-docs.deepseek.com.

## На что обратить внимание

- **Цифры, которые не объяснишь.** Каждую цифру интервьюер может попросить разобрать. «0.87 recall@5 — на каком датасете, сколько вопросов, кто размечал?» Ответ должен быть готов.
- **Расхождение с LinkedIn и GitHub.** Даты, названия, цифры должны совпадать везде.
- **Слишком много технологий.** 40 пунктов в Skills — признак, что ни в чём нет глубины. Оставь то, о чём выдержишь 10 минут вопросов.
- **Двухколоночные шаблоны.** Красивы, но ATS часто склеивает колонки в кашу.
- **Утечки.** Никаких сумм, бирж-аккаунтов, ссылок на приватные репозитории.
- **Ошибки в английском.** Прогони через LLM с промптом «исправь только грамматику, не меняй смысл и цифры», затем перечитай сам.

## Практика

- [ ] **Словарь вакансий.** Из 5–10 вакансий выпиши в `notes/resume.md` топ-15 ключевых слов. Отметь, какие у тебя честно есть.
- [ ] **Банк пунктов.** Напиши 10–12 пунктов по формуле (глагол + что + как + цифра): 4–5 про торговую систему, по 1–2 на каждый LLM-проект. Это банк, из которого будешь собирать версии под вакансии.
- [ ] **Сверка цифр.** Для каждой цифры в банке — ссылка на источник (eval-отчёт, лог стоимости, README). Без источника — пункт не идёт в резюме.
- [ ] **EN-версия.** Собери одну страницу по структуре из «Теории». Заголовок, summary, опыт, 4 проекта одной строкой, навыки, ссылки.
- [ ] **RU-версия.** Адаптируй (не переводи дословно). Заполни профиль на hh.ru и/или Хабр Карьере, приложи PDF.
- [ ] **Проверка ATS.** Скопируй текст из обоих PDF в текстовый редактор, проверь порядок и ссылки.
- [ ] **Ревью.** Сначала замени в копии резюме контакты на заглушки (или работай через Ollama). Дай LLM (DeepSeek; для сравнения тот же промпт — Claude или OpenAI) вакансию и резюме с промптом: «Ты рекрутер, у тебя 30 секунд. Позовёшь ли кандидата? Что мешает? Какие требования вакансии не закрыты?». Затем: «Ты нанимающий AI-инженер. Задай 5 вопросов по этим пунктам». Если на вопрос нет ответа — переформулируй пункт.
- [ ] **Файлы.** `Firstname_Lastname_AI_Engineer_EN.pdf` и `..._RU.pdf`, исходники в `notes/` или отдельном приватном репозитории.

## Готово, когда

- Резюме на 1 страницу на английском и на русском, в PDF с выделяемым текстом и рабочими ссылками.
- Заголовок Backend / AI Engineer, позиционирование в summary, каждый проект — одна строка с цифрой.
- Все цифры подтверждены и совпадают с README и LinkedIn.
- Есть банк пунктов для адаптации под конкретную вакансию.

10. Что не так в разделе Skills: «Python ●●●●○, LangChain ●●●●●, Leadership ●●●○○, Excel ●●●●●, ChatGPT ●●●●●»?

12. Что сделать с резюме, прежде чем отдать его на ревью DeepSeek, и почему?
    a) Ничего, там нет торговых данных b) Заменить контакты на заглушки или ревьюить локально через Ollama c) Перевести на китайский d) Сжать в картинку

## Ответы

1. ATS часто склеивает колонки и пропускает иконки и текст в графике; резюме разбирается неправильно, и ключевые слова теряются.
2. **b.** Она показывает действие, способ и измеримый результат — то, что ищет нанимающий менеджер.
3. «Responsible for» описывает обязанность, а не результат; «modern tools» ничего не значит; нет цифры и конкретики.
4. Большая часть работы AI Engineer — бэкенд и надёжность; опыт real-time системы с деньгами — редкое и прямо релевантное доказательство, а LLM-проекты показывают новый стек.
5. Стоит: число бирж, стримы, латентность, архитектурные решения, тесты, миграции. Не стоит: PnL, объёмы, балансы, аккаунты и детали стратегии.
6. **b.** Разные площадки, нормы (фото, зарплата, формат) и стиль формулировок.
7. Скопировать весь текст из PDF в обычный текстовый редактор: порядок, слова и ссылки должны сохраниться.
8. Под каждую вакансию резюме слегка адаптируется (заголовок, порядок и выбор пунктов); из банка собираешь версию за 10 минут, не переписывая.
9. Какой датасет и сколько вопросов (n) и кто его составил; что было baseline и что именно изменилось (гибридный поиск, реранкер); значима ли разница и как определена метрика.
10. Шкалы бессмысленны и ломают ATS; LangChain на «5/5» после месяцев — overclaiming; Excel и ChatGPT нерелевантны; Leadership не подтверждён.
11. Сделать хотя бы один сравнительный прогон через OpenAI/Claude и тогда честно указать их; в пункте про проект подать мультипровайдерность как плюс (OpenAI-compatible слой, сравнение на evals). Писать API, которые не вызывал, нельзя.
12. **b.** В резюме личные данные, а DeepSeek по своей политике хранит данные в Китае; для ревью контакты не нужны.
