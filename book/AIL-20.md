# 4.4 · Векторная БД + загрузка доков бирж  (AIL-20)

> **Неделя 4** · RAG · ⏱ ~8 ч (2 дня) · Проект

## Зачем это AI-инженеру

Игрушечный поиск на numpy из AIL-18 превращается в настоящий индекс: тысячи чанков, метаданные, фильтры, повторная загрузка без дублей. Ingestion-пайплайн — это 60% реальной работы над RAG в компаниях: источники меняются, ломаются, дублируются. На собеседовании спрашивают «как ты обновляешь индекс», «как фильтруешь по тенанту/источнику», «чем pgvector отличается от отдельной векторной БД» — после этой задачи у тебя будут ответы из собственного опыта.

## Теория

### Что даёт векторная БД сверх numpy

| Задача | numpy (AIL-18) | Векторная БД |
|---|---|---|
| Хранение | `.npy` в памяти | На диске, транзакции |
| Текст и метаданные | Отдельный JSON рядом | В той же записи |
| Фильтр «только OKX» | Руками маской | `WHERE exchange = 'okx'` |
| Обновление одного документа | Пересобрать массив | `DELETE` + `INSERT` |
| Миллионы векторов | Медленно и не влезает в память | ANN-индексы (HNSW, IVF) |

На твоём масштабе (несколько тысяч — десятки тысяч чанков) точный перебор (brute force) занимает миллисекунды. Поэтому выбор хранилища здесь — вопрос удобства и знакомости, а не скорости.

### ANN: приближённый поиск, коротко

Точный поиск сравнивает запрос со всеми векторами: O(N). При миллионах векторов это медленно, поэтому используют **приближённый поиск ближайших соседей (ANN)**:

- **HNSW** — многоуровневый граф «соседей»; поиск идёт жадно от дальних связей к ближним. Быстрый, точный, но жрёт память. Стандарт в Qdrant, pgvector, многих других.
- **IVF** — векторы разбиты на кластеры; ищем только в нескольких ближайших кластерах.

Цена ANN — **recall < 100%**: иногда настоящий ближайший сосед не находится. Важная практическая ловушка — **фильтр + ANN**: если сначала найти top-10 по вектору, а потом отфильтровать «только Gate», может остаться 0 результатов (post-filtering). Хорошие БД умеют фильтровать внутри поиска или до него (pre-filtering, partition). На твоём объёме с точным поиском этой проблемы почти нет, но знать её обязательно.

### Три варианта хранилища

**sqlite-vec** — расширение SQLite. Вектор хранится в виртуальной таблице `vec0`, поиск — обычным SQL. Один файл, ноль серверов, знакомый тебе инструмент (в приложении у тебя SQLite с WAL). Делает точный поиск (brute force), чего на твоём масштабе более чем хватает. Проект молодой: синтаксис и возможности (метаданные-колонки, partition keys, выбор метрики) развиваются — сверяйся с README и документацией той версии, которую ставишь.

**pgvector** — расширение PostgreSQL: тип `vector`, операторы расстояния (`<->` L2, `<=>` косинусное расстояние, `<#>` отрицательное скалярное произведение), индексы HNSW и IVFFlat. Лучший выбор, если в проекте уже есть Postgres: векторы рядом с бизнес-данными, транзакции, JOIN.

**Qdrant** — отдельная векторная БД (Rust), с REST/gRPC API, коллекциями, payload-фильтрами и HNSW. Удобна, когда векторов много, нужен масштаб и продвинутые фильтры. Плата — ещё один сервис в инфраструктуре.

Для проекта бери **sqlite-vec**, остальные — прочитать для сравнения.

### sqlite-vec: схема

Идея: обычная таблица с текстом и метаданными + виртуальная таблица с векторами, связанные по `rowid`.

```sql
CREATE TABLE IF NOT EXISTS chunks (
  id            INTEGER PRIMARY KEY,
  chunk_key     TEXT UNIQUE NOT NULL,   -- sha256(url + section + text)
  exchange      TEXT NOT NULL,          -- bybit | okx | binance | gate
  url           TEXT NOT NULL,
  section       TEXT,
  text          TEXT NOT NULL,
  doc_hash      TEXT NOT NULL,          -- hash of the whole page content
  embed_model   TEXT NOT NULL,
  fetched_at    TEXT NOT NULL
);

-- Check the sqlite-vec docs for the exact vec0 options of your version
CREATE VIRTUAL TABLE IF NOT EXISTS vec_chunks USING vec0(
  embedding float[384]                  -- must equal your model's dimension
);
```

Подключение из Python (иллюстративно, сверяй с README):

```python
import sqlite3
import sqlite_vec

db = sqlite3.connect("index.db")
db.enable_load_extension(True)
sqlite_vec.load(db)
db.enable_load_extension(False)
```

Если `enable_load_extension` отсутствует — твой Python собран без поддержки расширений SQLite (бывает с системным Python на macOS); поставь Python через Homebrew/pyenv/uv.

Вставка и KNN-запрос:

```python
from sqlite_vec import serialize_float32

cur = db.execute(
    "INSERT INTO chunks (chunk_key, exchange, url, section, text, doc_hash, embed_model, fetched_at) "
    "VALUES (?, ?, ?, ?, ?, ?, ?, ?) ON CONFLICT(chunk_key) DO NOTHING",
    (key, exchange, url, section, text, doc_hash, MODEL, now),
)
if cur.rowcount == 1:  # inserted, not a duplicate
    db.execute("INSERT INTO vec_chunks (rowid, embedding) VALUES (?, ?)",
               (cur.lastrowid, serialize_float32(vec)))

rows = db.execute(
    """
    SELECT c.exchange, c.url, c.section, c.text, v.distance
    FROM vec_chunks v JOIN chunks c ON c.id = v.rowid
    WHERE v.embedding MATCH ? AND k = ?
    ORDER BY v.distance
    """,
    (serialize_float32(qvec), 10),
).fetchall()
```

Обрати внимание на `distance`: это **расстояние** (меньше = ближе), а не сходство. По умолчанию — L2; для нормализованных векторов порядок тот же, что у косинуса (AIL-18).

### Фильтр по метаданным с векторным поиском

Наивный вариант — найти top-k по всей базе, потом `WHERE c.exchange = 'okx'` в JOIN. Это **post-filtering**: при k=10 может оказаться, что все 10 — от Bybit, и для OKX ты получишь ноль. Варианты:

1. **Метаданные/partition key прямо в `vec0`** — в свежих версиях sqlite-vec можно объявить колонку вроде `exchange text` (или `exchange text partition key`) в виртуальной таблице и фильтровать по ней в том же KNN-запросе. Проверь в документации своей версии.
2. **Отдельная `vec0`-таблица на биржу** — грубо, но надёжно.
3. **Большой k + фильтр + обрезка** (взять k=200, отфильтровать, оставить 10) — простой компромисс на малом объёме.
4. **Точный поиск в numpy по подмножеству**: вытащить векторы нужной биржи и посчитать как в AIL-18 — на твоём объёме тоже вариант.

Выбери 1, если поддерживается; иначе 3. Главное — тест: «поиск с фильтром `gate` всегда возвращает k результатов от Gate, если они есть».

### Ingestion-пайплайн

```
sources.yaml ─► fetch (GET, кэш на диск) ─► clean (HTML → Markdown)
     ─► chunk (стратегия из AIL-19) ─► dedupe (chunk_key) ─► embed (батчами)
     ─► upsert в SQLite ─► отчёт: страниц, чанков новых/старых/удалённых
```

Принципы, которые ты знаешь из бэкенда, здесь работают так же:

- **Идемпотентность.** Повторный запуск без изменений в доках не меняет базу. Достигается детерминированным ключом чанка: `sha256(url + section + text)`, и `UNIQUE` в схеме.
- **Инкрементальность.** Храни `doc_hash` страницы. Если хэш не изменился — страницу пропускаешь целиком (ни chunking, ни эмбеддинги). Если изменился — удаляешь старые чанки этой страницы (`DELETE ... WHERE url = ?` и соответствующие строки `vec_chunks`) и вставляешь новые.
- **Кэш сырья.** Скачанный HTML сохраняй в `raw/<exchange>/<slug>.html`. Отлаживать чистку и chunking ты будешь много раз, а качать заново — незачем и невежливо к сайту.
- **Батчи эмбеддингов** и кэш (AIL-18).
- **Транзакции.** Обработка одной страницы — одна транзакция: либо все её чанки обновились, либо ничего.
- **Записывай `embed_model`.** Сменишь модель — по этому полю видно, что индекс надо перестроить.

Источники (публичные страницы, никаких ключей и подписанных запросов):

| Биржа | Где доки | Особенности |
|---|---|---|
| Bybit | [bybit-exchange.github.io/docs](https://bybit-exchange.github.io/docs/) | Много страниц, по одной на эндпоинт; удобно для chunking |
| OKX | [okx.com/docs-v5/en](https://www.okx.com/docs-v5/en/) | Одна огромная страница; режь по заголовкам, URL раздела = страница + якорь |
| Binance | [developers.binance.com/docs](https://developers.binance.com/docs/) | Разделы spot / derivatives; бери нужные тебе (USDⓈ-M Futures) |
| Gate | [gate.com/docs/developers/apiv4](https://www.gate.com/docs/developers/apiv4/) | Большая страница, похожа по структуре на OKX |

Список стартовых URL держи в `sources.yaml`, а не в коде. Начни с ограниченного набора разделов (торговля, позиции, funding, лимиты, коды ошибок, WebSocket), а не со всей документации — индекс в несколько тысяч чанков уже полноценный.

Вежливость к сайтам: пауза между запросами (0.5–1 с), понятный User-Agent без личных данных, уважай `robots.txt`, кэшируй. Если страница рендерится JavaScript'ом и в HTML пусто — сначала поищи, нет ли исходников доков в виде Markdown в публичном GitHub-репозитории биржи, и лишь потом думай о headless-браузере.

HTML → Markdown: сначала вырежи основной контент (контейнер статьи; найди CSS-селектор в devtools), потом конвертируй (`markdownify`, `html2text` или `trafilatura`). Проверяй глазами: таблицы параметров и блоки кода должны уцелеть.

### URL с якорем

Для цитат (AIL-23) у чанка должен быть URL, ведущий как можно ближе к месту: `https://.../docs-v5/en/#order-book-trading-trade-post-place-order`. Якоря обычно есть в `id` у заголовков HTML — сохрани их на этапе чистки (например, вставляя `{#anchor}` или отдельным полем) и запиши в `url` чанка.

## DeepSeek и Ollama: как это сделать у нас

Индексация — единственное место проекта, где модель вызывается тысячи раз подряд, и это только эмбеддинги. У DeepSeek их нет (глава 4.1 · Эмбеддинги руками на numpy), поэтому весь ingestion работает **локально и бесплатно**: Ollama или Sentence Transformers. Облачный ключ для `ingest.py` не нужен вообще.

### `embed.py` с выбором бэкенда

```python
# Illustrative: one interface, backend chosen by env vars (EMBED_BACKEND, EMBED_MODEL)
import os
import numpy as np

BACKEND = os.environ.get("EMBED_BACKEND", "ollama")   # ollama | st | openai
MODEL = os.environ["EMBED_MODEL"]                     # e.g. bge-m3 / BAAI/bge-m3

def embed(texts: list[str]) -> np.ndarray:
    if BACKEND == "ollama":
        import ollama
        res = ollama.embed(model=MODEL, input=texts, truncate=False, keep_alive="10m")
        return np.asarray(res["embeddings"], dtype=np.float32)
    if BACKEND == "st":
        from sentence_transformers import SentenceTransformer
        st = _cached_st(MODEL)                        # TODO: load once, reuse
        return st.encode(texts, normalize_embeddings=True, batch_size=32).astype(np.float32)
    raise ValueError(f"unknown backend {BACKEND}")    # 'openai' is optional, for comparison

def model_tag() -> str:
    return f"{BACKEND}:{MODEL}"                       # store this in chunks.embed_model
```

Что это меняет в схеме и пайплайне:

- **Размерность `vec0` = размерность модели.** У `bge-m3` 1024 (по карточке BAAI/bge-m3), значит `embedding float[1024]`, а не `float[384]` из примера выше. Не бери число из памяти: вызови `len(embed(["test"])[0])` и подставь результат.
- **`embed_model` хранит и бэкенд**: `ollama:bge-m3` и `st:BAAI/bge-m3` — разные индексы, даже если имя модели одно (глава 4.1).
- **Батчи.** `input` у `/api/embed` принимает список. Подбирай размер батча (16–64 чанка) по скорости на своём Mac: слишком большой батч не ускоряет и ест память.
- **Модель в памяти.** Первый вызов грузит модель (поле `load_duration` в ответе). Параметр `keep_alive` держит её загруженной между запросами — важно для `search.py`, иначе каждый поиск начинается с загрузки. Обратная сторона на твоём M2 с 8 GB, где рядом работает арбитражное приложение: загруженная модель держит память, пока не истечёт `keep_alive`. Для `ingest.py` хватает короткого `keep_alive`; после индексации проверь `ollama ps` и выгрузи модель (`ollama stop <модель>`). Не держи одновременно эмбеддинг-модель, генератор и реранкер, не прикинув их суммарный размер.
- **Ollama должен быть запущен.** Если сервер не отвечает на `localhost:11434`, `ingest.py` должен падать с понятным сообщением («запусти Ollama»), а не с трейсбеком на 40 строк.
- **Латентность поиска** теперь без сети: эмбеддинг вопроса локальной моделью на Apple Silicon занимает порядка десятков миллисекунд, если модель уже загружена. Не верь этой цифре на слово — измерь.

### Сравнение провайдеров для индексации

| Что нужно индексу | Claude | OpenAI | DeepSeek | Ollama / Sentence Transformers |
|---|---|---|---|---|
| Эмбеддинги тысяч чанков | Нет своих (Voyage AI) | Да, платно за токены, rate limits | **Нет** | Да, бесплатно; ограничено скоростью Mac |
| Батч в одном запросе | — | Да (список в `input`) | — | Да (список в `input`; у ST — `batch_size`) |
| Сеть при поиске | — | Запрос к API на каждый вопрос | — | Нет, всё локально |
| Ключ в `.env` для `ingest.py` | — | `OPENAI_API_KEY` | — | Не нужен |

Практика этой главы делается целиком на локальном бэкенде. OpenAI-эмбеддинги — только «для сравнения» и только в отдельный `index_openai.db` (смешивать векторы разных моделей в одной таблице нельзя).

5. Документация конвертера HTML → Markdown, который выберешь (`markdownify` или `html2text` на PyPI, или `trafilatura`) — параметры для заголовков, таблиц и блоков кода (≈15 мин).
6. Перечитай [справку Ollama `/api/embed`](https://docs.ollama.com/api/embed) (≈10 мин): `input` списком, `truncate`, `keep_alive`, поля `load_duration` и `prompt_eval_count`. Вынеси, как держать модель загруженной во время `ingest.py` и `search.py`.

## На что обратить внимание

- **Несовпадение размерности** `float[N]` в `vec0` и модели → ошибка вставки (это хорошо, лучше, чем молча).
- **`distance` ≠ similarity.** Меньше — ближе. Не сортируй по убыванию по привычке.
- **Post-filtering** возвращает меньше k результатов или ноль. Тестируй фильтр на редкой бирже.
- **Дубли** при повторной загрузке: ключ не детерминирован (включает время или случайный id). Ключ только из содержимого.
- **Осиротевшие векторы**: удалил строки из `chunks`, забыл `vec_chunks` → в выдаче `JOIN` пропадает строка, а k фактически меньше. Удаляй в одной транзакции.
- **Мусор навигации** в Markdown — главный враг качества (см. AIL-19). Проверь 10 случайных чанков глазами.
- **Таблицы в HTML** с `colspan`/вложенными списками конвертеры ломают. Иногда проще превратить таблицу в список «параметр: тип, обязательность, описание».
- **Один URL на всю страницу OKX/Gate** — цитата будет бесполезной. Нужны якоря.
- **Блокировки и капча** при агрессивном скачивании. Паузы и кэш.
- **Безопасность:** проект не знает ключей бирж и не делает к ним никаких приватных запросов; в `.env` только ключ провайдера LLM (DeepSeek; OpenAI/Anthropic — если делаешь сравнение), `.env` в `.gitignore`. При локальных эмбеддингах индексации ключ не нужен вовсе. Индекс (`index.db`) и `raw/` тоже в `.gitignore` — их можно пересобрать скриптом.

## Практика

Структура проекта `exchange-docs-rag/`:

```
exchange-docs-rag/
  sources.yaml          # exchange -> start URLs, content selector
  rag/
    fetch.py            # GET + disk cache in raw/
    clean.py            # HTML -> Markdown, keep anchors, tables, code
    chunk.py            # strategy chosen in AIL-19
    embed.py            # batch embeddings + cache
    store.py            # sqlite-vec schema, upsert, search
  ingest.py             # CLI: python ingest.py [--exchange okx]
  search.py             # CLI: python search.py "query" --exchange okx -k 5
  tests/test_store.py
```

- [ ] **`sources.yaml`** для Bybit, OKX, Binance (USDⓈ-M Futures), Gate: стартовые URL выбранных разделов, CSS-селектор контента, пауза между запросами.
- [ ] **`fetch.py`**: скачивает публичные страницы обычным GET, кладёт в `raw/<exchange>/`, повторно не качает, если файл свежее N часов (флаг `--refresh` для принудительного).
- [ ] **`clean.py`**: вырезает контент по селектору → Markdown; сохраняет якоря заголовков. Проверь на 2 страницах каждой биржи глазами.
- [ ] **`chunk.py`**: стратегия-победитель из AIL-19 (скорее всего по заголовкам с breadcrumbs), у каждого чанка: `exchange`, `url` (с якорем), `section`, `text`.

## Ответы

1. Ради хранения на диске, метаданных и фильтров, обновления отдельных документов, транзакций и масштабирования (ANN) — а не ради скорости на малом объёме.
2. Граф ближайших соседей в несколько уровней, по которому поиск идёт жадно. Цена — приближённость: recall меньше 100%, плюс память на граф и сложности с фильтрами.
3. Если сначала взять top-10 по всей базе, а потом отфильтровать Gate, среди десяти может не оказаться ни одного чанка Gate, хотя они есть в базе: результат пустой или неполный. Нужен фильтр внутри/до поиска или больший k.
4. b) по возрастанию: это расстояние, меньше — ближе.
5. Детерминированный ключ чанка из его содержимого (`sha256(url + section + text)`) с `UNIQUE` и `ON CONFLICT DO NOTHING`, плюс пропуск страниц с неизменным хэшем.
6. `uuid4()` случаен: каждый запуск даёт новый ключ, и `UNIQUE` никогда не срабатывает — каждый прогон дублирует все чанки. Ключ должен зависеть только от содержимого.
7. Чтобы целиком пропускать неизменённые страницы (без chunking и эмбеддингов) и понимать, что страница изменилась и её старые чанки надо удалить.
8. b).
9. OKX — одна огромная страница; без якоря ссылка в ответе ведёт в начало многостраничного документа, и проверить утверждение невозможно.
10. Иначе сбой посередине оставит страницу без чанков или с дублями старой и новой версии, а `vec_chunks` разойдётся с `chunks` (осиротевшие векторы).
11. Эмбеддинг вопроса через API (сетевой запрос, десятки-сотни мс); точный KNN по нескольким тысячам векторов в SQLite — миллисекунды. С локальной Ollama сети нет, и эмбеддинг загруженной моделью обычно быстрее облачного, но всё равно, как правило, дольше KNN — измерь.
12. Вставка упадёт с ошибкой несовпадения размерности: у `bge-m3` 1024 измерения. Размерность берут из реального вектора (`len(embed(["test"])[0])`), а при смене модели индекс перестраивают целиком.
13. Ollama выгрузила модель из памяти, и первый запрос включает её загрузку (видно по `load_duration`). Держи модель загруженной через `keep_alive` и прогревай её одним запросом при старте; в замерах отделяй прогрев.
14. b). Генерация в `ingest.py` не участвует, а эмбеддинги делает Ollama или Sentence Transformers локально.
