# 1.2 · Репозиторий для учёбы: git, notes/, структура  (AIL-56)

> **Неделя 1** · Подготовка · ⏱ ~1,5 ч · Практика

## Зачем это AI-инженеру

Через 13 недель этот репозиторий станет портфолио: проекты, таблицы evals, заметки, по которым видно, как ты думаешь. Работодатель смотрит GitHub раньше резюме, и аккуратная история коммитов с понятной структурой говорит больше, чем строчка «знаю RAG». Кроме того, в AI-проектах много секретов (ключи API) и больших данных (базы, эмбеддинги), и привычку не коммитить лишнее лучше выработать в первый день.

## Теория

### 1. Один репозиторий на всю учёбу — monorepo

Варианты: репозиторий на каждый проект или один на всё. Для учёбы удобнее один (`ai-engineering-journey`), где каждый крупный проект — отдельная папка со своим окружением. Позже, на неделе 12, лучшие проекты можно вынести в отдельные публичные репозитории для портфолио (или сделать этот публичным, предварительно проверив историю на секреты и личные данные).

```
ai-engineering-journey/
├── README.md                 # the plan + progress log
├── .gitignore
├── .env.example              # variable NAMES only, no values
├── notes/
│   ├── python-vs-ts.md       # AIL-1
│   ├── llm-basics.md         # AIL-3
│   └── week-01.md            # daily notes, Friday review
├── exercises/
│   ├── week-01/
│   │   ├── spread.py
│   │   └── stats.py
│   └── week-02/
└── projects/
    ├── 01-trade-analyst-bot/ # own pyproject.toml, own README
    └── 02-exchange-docs-rag/
```

Принципы:
- **`notes/`** — заметки своими словами. Это не мусор: перед собеседованием ты будешь перечитывать именно их.
- **`exercises/week-NN/`** — короткие упражнения, можно с одним общим окружением на неделю или на весь `exercises/`.
- **`projects/NN-name/`** — у каждого проекта свой `pyproject.toml`, `uv.lock`, `README.md`, `tests/`. Номер в имени сохраняет порядок.

### 2. Что такое `.gitignore` и чего он не делает

`.gitignore` — список шаблонов путей, которые git не предлагает добавить. Синтаксис:

```
.venv/          # directory anywhere
*.db            # by extension, anywhere
/build          # only at repo root
!keep.db        # exception from a previous rule
```

Важно: **`.gitignore` не действует на файлы, которые уже отслеживаются.** Если `.env` уже закоммичен, добавление его в `.gitignore` ничего не убирает из истории. Нужно `git rm --cached .env` (перестать отслеживать, файл на диске остаётся), а если там был ключ — **отозвать ключ** (подробно в AIL-3), потому что из истории он никуда не делся.

Проверка, что файл игнорируется и каким правилом: `git check-ignore -v .env`.

### 3. Что игнорировать в Python/AI-репозитории

| Категория | Шаблоны | Почему |
|---|---|---|
| Окружение | `.venv/`, `venv/` | создаётся `uv sync`, как `node_modules` |
| Кеши Python | `__pycache__/`, `*.pyc`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/` | генерируются автоматически |
| Секреты | `.env`, `.env.*`, но `!.env.example` | ключи API |
| Базы данных | `*.db`, `*.sqlite`, `*.sqlite3`, `*.db-wal`, `*.db-shm` | копии торговой базы, векторные индексы; WAL-файлы рядом с базой |
| Данные | `data/raw/`, `*.parquet` (по ситуации) | большие файлы, могут быть личными |
| Ноутбуки | `.ipynb_checkpoints/` | автосохранения Jupyter (AIL-57) |
| Система/IDE | `.DS_Store`, `.idea/` | мусор macOS и IDE |

`uv.lock` **коммитить нужно** — это аналог `package-lock.json`, он делает окружение воспроизводимым. `.vscode/` — по вкусу: `settings.json` с выбором интерпретатора полезно хранить, личное — нет.

Готовый шаблон GitHub: [Python.gitignore](https://github.com/github/gitignore/blob/main/Python.gitignore). Можно взять его и дописать снизу свой блок (секреты, базы).

### 4. `.env.example` — контракт без секретов

```
# .env.example — copy to .env and fill in
# main: DeepSeek (cloud, cheap) + Ollama (local, free)
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=
OLLAMA_BASE_URL=http://localhost:11434/v1
OLLAMA_MODEL=
# optional, for comparison
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
```

В git лежит только список имён переменных (и несекретные значения по умолчанию вроде адреса локальной Ollama). Человек (или ты через полгода) клонирует репозиторий, копирует файл в `.env` и вписывает свои значения. Сами ключи появятся в главе 1.5 · Видео Карпатого + ключи API (AIL-3).

### 5. Особый случай: данные арбитражного приложения

В проектах курса (бот-аналитик на неделе 3, MCP-сервер на неделе 9) ты будешь работать с данными своих сделок. Правила с первого дня:
- в учебный репозиторий **никогда не попадает** ни боевая, ни демо-база приложения, ни её копии, ни выгрузки реальных сделок;
- для работы берётся копия базы через `VACUUM INTO` (база в режиме WAL, обычный `cp` может дать несогласованный файл), и лежит эта копия **вне** репозитория или в игнорируемой папке;
- для публичного портфолио — только **выдуманные** демо-данные, сгенерированные скриптом.

Правило `*.db` в `.gitignore` — страховка, а не замена этой дисциплине.

### 6. Коммиты, которые приятно читать

- Один коммит — одна логическая единица: «week-01: spread and csv stats exercises», а не «update».
- Коммить каждый день в конце сессии, в пятницу — обзор недели в `notes/week-NN.md`.
- Перед каждым коммитом: `git status` и `git diff --staged` — глазами, что именно уходит. Это 10 секунд, которые ловят случайный `.env` или дамп базы.

### 7. Приватный удалённый репозиторий

Создать можно в веб-интерфейсе GitHub (New repository → Private) или через [GitHub CLI](https://cli.github.com): `gh repo create ai-engineering-journey --private --source=. --remote=origin`. Ветки в учебном репозитории не обязательны — работаешь в `main`; ветка пригодится для экспериментов, которые могут не взлететь.

## DeepSeek и Ollama: как это сделать у нас

Учишься ты на DeepSeek (облако, дёшево, OpenAI-совместимый API, серверы в Китае) и Ollama (локальные модели); Claude и OpenAI — для сравнения. Для репозитория это меняет три мелочи:

- **`.env.example`** перечисляет `DEEPSEEK_API_KEY` и имена моделей как основные, ключи Anthropic/OpenAI — как необязательные (шаблон выше). Имена моделей держи в окружении, не в коде: у DeepSeek они меняются.
- **Веса моделей в репозиторий не попадают.** Ollama хранит модели в `~/.ollama`, вне репозитория, — так и оставь. Но на неделе 11 (LoRA) появятся свои файлы весов и адаптеров: добавь в игнор `*.gguf`, `*.safetensors` и папку `models/` заранее — это гигабайты.
- **Граница данных проходит и через заметки.** Ответы DeepSeek на учебные вопросы можно сохранять в `notes/`. А вот всё, что ты будешь делать с данными своих сделок, пойдёт только через локальную Ollama, и результаты таких прогонов (даже «просто вывод модели») — в игнорируемую папку, потому что модель пересказывает твои реальные цифры.

| | Claude / OpenAI | DeepSeek | Ollama |
|---|---|---|---|
| Секрет в `.env` | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | `DEEPSEEK_API_KEY` | нет (адрес `localhost` — не секрет) |
| Что может попасть в git по ошибке | ключ | ключ | веса модели, вывод по реальным данным |
| Что игнорировать | `.env` | `.env` | `*.gguf`, `*.safetensors`, `models/`, `outputs/` с реальными данными |

## На что обратить внимание

- **Сначала `.gitignore`, потом `git add`.** Если сделать `git add .` до создания `.gitignore`, в индекс попадут `.venv` и всё остальное.
- **`git add .` — опасная привычка** в репозитории с данными. Добавляй осознанно или хотя бы смотри `git status` перед коммитом.
- **Уже закоммиченный секрет не исправляется новым коммитом.** История хранит всё; даже переписанная история могла уйти в форк или кеш. Единственная надёжная мера — отозвать ключ.
- **Большие файлы.** GitHub отклоняет файлы больше 100 МБ, и даже меньшие раздувают историю навсегда. Датасеты и индексы — в игнор, в README — команда, как их пересоздать.
- **Вывод ноутбуков** может содержать данные и даже значения переменных окружения, если их напечатали. Об этом в AIL-57.
- **Личные данные в заметках.** Если планируешь сделать репозиторий публичным, не пиши в `notes/` реальные суммы, балансы, названия аккаунтов.

12. Ты прогнал локальную модель Ollama по копии своей базы и сохранил её ответы в `notes/trades-summary.md`. Данные никуда не отправлялись. Можно это коммитить?

## Ответы

1. Нет. Ключ остался в истории первого коммита (и, если был push, на GitHub). Нужно немедленно отозвать ключ в консоли провайдера и выпустить новый.
2. **b.** `--cached` убирает файл из индекса; `git rm` без флага удалит и с диска.
3. Да. Это lock-файл, фиксирующий точные версии всех зависимостей, как `package-lock.json`; без него окружение у тебя и на CI может отличаться.
4. Правило `.env.*` поймало бы и `.env.example`; `!` делает исключение, чтобы шаблон с именами переменных попадал в git.
5. SQLite в режиме WAL держит рядом с базой файлы журнала и общей памяти; в них могут быть свежие данные, и в git им не место, как и самой базе.
6. `.gitignore` создан после `git add .`: в первый коммит уже попали `.venv` и всё остальное, включая возможные секреты. Сначала `.gitignore`, потом `add`.
7. `git check-ignore -v <путь>` — покажет файл и строку правила.
8. База в режиме WAL: часть данных может лежать в `-wal`, и простое копирование файла во время работы даёт несогласованную копию. `VACUUM INTO` делает целостный снимок средствами самого SQLite.
9. **c.** Только вымышленные данные. Даже демо-база и «обезличенная» выгрузка раскрывают реальную активность и не нужны для демонстрации.
10. Не коммитить: положить в игнорируемую папку `data/` и описать в README, откуда его скачать или каким скриптом сгенерировать.
11. Пустой `DEEPSEEK_API_KEY=` и адрес локальной Ollama — нормально: это имена и несекретное значение по умолчанию. Строка с настоящим ключом — утечка, ключ надо отозвать. У локальной Ollama нет аутентификации: она слушает только `localhost`, SDK `openai` требует какую-то строку в `api_key`, но Ollama её игнорирует.
12. Нет. Локальная модель защищает данные от отправки наружу, но её ответ пересказывает твои реальные сделки; в git (а потом, возможно, в публичный репозиторий) он попадать не должен. Такие выводы — в игнорируемую папку (`outputs/`).
